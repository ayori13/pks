# Локальное хранилище данных SQLite

Я использовал базу данных SQLite для локального хранения заметок. Файл `app.db` создается и хранится в приватной директории приложения на устройстве пользователя, что обеспечивает безопасность данных.

## Структура таблицы

Таблица `notes` имеет следующую схему:
- `id` — целочисленный первичный ключ с автоинкрементом
- `title` — текстовое поле для заголовка заметки (обязательное)
- `body` — текстовое поле для содержимого заметки (обязательное)
- `created_at` — целочисленное поле для хранения времени создания в миллисекундах
- `updated_at` — целочисленное поле для времени последнего обновления

## Реализация операций CRUD

### Создание заметок
При добавлении новой заметки я создаю объект `Note`, заполняя поля `created_at` и `updated_at` текущим временем. Затем вызываю метод `insertNote`, который преобразует объект в формат `Map` и выполняет SQL-запрос `INSERT` для сохранения данных в таблицу.

### Чтение заметок
Для получения списка заметок я реализовал метод `fetchNotes`, который выполняет SQL-запрос `SELECT` с сортировкой по дате создания (новые заметки отображаются первыми). Полученные данные преобразуются из формата `Map` обратно в объекты `Note` и возвращаются в виде списка.

### Обновление заметок
При редактировании заметки создается обновленная копия объекта с измененными полями и новым значением в поле `updated_at`. Затем выполняется SQL-запрос `UPDATE`, который изменяет запись в таблице по идентификатору.

### Удаление заметок
Для удаления заметок я реализовал SQL-запрос `DELETE` по идентификатору записи. Пользователь может удалять заметки двумя способами: через иконку корзины в интерфейсе или с помощью свайпа элемента в списке.

Все операции с базой данных выполняются асинхронно через `Future`, что предотвращает блокировку пользовательского интерфейса во время выполнения запросов.
