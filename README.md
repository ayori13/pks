# Ход работы

## 1. Выбор и настройка API

Для работы с данными я выбрал MockAPI (Вариант B) — сервис mockapi.io, который позволяет работать с тестовыми REST API.

**Базовый URL:** `https://691c4f723aaeed735c905921.mockapi.io/api/`

**Основные эндпоинты:**
- `GET /notes` — получение списка записей с поддержкой параметров пагинации
- `POST /notes` — создание новой записи
- `DELETE /notes/{id}` — удаление записи по идентификатору

**Пример структуры данных от API:**
```json
{
  "id": "1",
  "name": "Emily Glover",
  "avatar": "https://example.com/image.jpg",
  "createdAt": "2025-11-18T03:14:15.877Z"
}
```

## 2. Модель данных и слой репозитория

Я реализовал модель данных `Note`, соответствующую структуре ответа от API:
```dart
class Note {
  final int id;
  final String name;
  final String avatar;
  final String createdAt;

  Note({
    required this.id,
    required this.name,
    required this.avatar,
    required this.createdAt,
  });

  factory Note.fromJson(Map<String, dynamic> json) {
    return Note(
      id: json['id'] is String ? int.tryParse(json['id']) ?? 0 : (json['id'] ?? 0),
      name: json['name'] ?? '',
      avatar: json['avatar'] ?? '',
      createdAt: json['createdAt'] ?? '',
    );
  }

  Map<String, dynamic> toJson() {
    return {
      'id': id.toString(),
      'name': name,
      'avatar': avatar,
      'createdAt': createdAt,
    };
  }
}
```

Для работы с API я создал класс `NotesRepository`, который:
- Использует `Dio` через общий `ApiClient`
- Реализует полный набор CRUD-операций:
  - `list()` — получение списка с пагинацией
  - `get()` — получение конкретной записи
  - `create()` — создание новой записи
  - `update()` — обновление существующей записи
  - `delete()` — удаление записи

## 3. Реализация пагинации

MockAPI поддерживает пагинацию через параметры `?page=` и `?limit=`.

**Клиентская реализация:**
- Использовал `ScrollController` для отслеживания прокрутки списка
- При достижении конца списка вызывается метод `_loadMore()` для загрузки следующей страницы
- Реализовал защиту от рекурсивных вызовов через флаги `_loading` и `_canLoadMore`
- В текущей версии приложение загружает все доступные страницы, но можно легко ограничить количество

## 4. Обработка ошибок и настройка времени ожидания

**Настройка таймаутов в Dio:**
```dart
connectTimeout: const Duration(seconds: 10),
receiveTimeout: const Duration(seconds: 10),
```

**Обработка ошибок:**
- Все сетевые запросы обернул в блоки `try/catch`
- При возникновении ошибок показываю пользователю информативные уведомления через `SnackBar`
- Добавил проверку `if (mounted)` перед вызовами `setState()` для предотвращения ошибок после удаления виджета

## 5. Пользовательский опыт: состояния интерфейса

| Состояние       | Реализация                                                                                                       |
|-----------------|------------------------------------------------------------------------------------------------------------------|
| **Загрузка**    | `CircularProgressIndicator` в центре экрана при первичной загрузке; индикатор внизу списка при пагинации; поддержка pull-to-refresh через `RefreshIndicator` |
| **Пустой список** | Можно легко добавить через проверку `_items.isEmpty && !_loading`, хотя в mockapi редко встречается пустой ответ |
| **Ошибка**      | Всплывающее уведомление `SnackBar` с описанием ошибки; приложение продолжает работать стабильно при сетевых проблемах |
